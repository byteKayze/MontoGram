# Local data batch: source review and limits

Six independent actions: bookmark folders (M36); explicit own-note export (M39); portable quick-reply backup/import with preview (M40); local model counts/serialized byte sizes (M42); bookmark label/reference export without message bodies (M62); multi-select atomic note deletion (M63). These are SOURCE implementations; a built APK and Android runtime acceptance are separate evidence.

Only the current `(account slot, self user)` owner is admitted. Export discloses fields and record count before the document picker, reacquires a fresh owner afterwards, and requires final confirmation. Portable files contain intentional dialog/message references where disclosed, but no owner identifiers, original internal IDs, encrypted store bytes, credentials or messages fetched from Telegram. Note exports carry the user's own note text. Template files are unencrypted: the selected document provider receives their contents. No persistent URI grants are taken. The result URI exists only for one result-to-resume handoff and current operation, and is not saved in fragment arguments/preferences/state.

There is one shared provider-facing worker for settings backup and these transfers. Read/write payloads are bounded (2 MiB absolute; template import262144 bytes; settings import4096 bytes), with a15-second deadline. Cancel/timeout wipes request-owned active buffers before descriptor close or cancellation, including when a fake provider remains blocked. A provider can keep its own copy; Android/JVM/IME/provider memory erasure is not guaranteed. A timed-out provider disables further transfers until process restart; no replacement threads are spawned. Partial destination documents can remain after failed/cancelled export. Highly escaped maximum-size notes can exceed the export cap; export rejects them without truncating or changing app data.

Imports strictly decode before preview; exact `(label,text)` duplicates are skipped, new IDs are allocated by the target, overflow rejects the entire merge. Apply is tied to the decoded model's canonical digest and the target owner/revision. Bulk note deletion validates the whole selected-ID set before one immutable model commit. Unknown/stale IDs cannot cause partial deletion. A retained storage commit can be unconfirmed: UI asks to refresh rather than claiming rollback.

Folders are one level, NFC-normalized, trimmed, case-sensitive, max32 live nonempty names of max32 UTF-16 units. Payload remains capped at32 KiB. Unfiled-only data uses MBK1; folder data uses MBK2. Older clients cannot read MBK2; this is disclosed before folder editing. Dissolving a folder explicitly moves its bookmarks to unfiled and never deletes them. Counts/bytes are model serialization sizes, not storage, RAM, provider quota or performance measurements. Existing owner-specific managers remain the route for clearing local data.
