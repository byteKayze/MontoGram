# Безопасность

## Сообщение о проблеме

Не публикуйте уязвимость вместе с действующими ключами, Telegram auth/session
данными, кодами входа или содержимым личных сообщений. Если для репозитория
включены private vulnerability reports, используйте их. Иначе сначала свяжитесь
с создателем: [@gimmextraligma](https://t.me/gimmextraligma).

Укажите версию/ABI, затронутую функцию, минимальные шаги и ожидаемый результат.
Примеры должны использовать собственные тестовые данные. Передавайте публичный
отчёт после согласованного исправления; срок ответа пока не гарантируется.

## Границы alpha

Alpha не сопровождается обещанием отсутствия уязвимостей. Успешная компиляция,
проверка подписи или regex secret scan не заменяют runtime/security audit.
В каждом релизе перечисляются фактически выполненные проверки и ограничения.

Montogram не предоставляет ложный Premium, снятие серверных прав, обход
protection/TTL или экспорт чужих auth-сессий. Локальный creator badge — элемент
Montogram, а не Telegram verification или авторизация.

## Перед публикацией

- Подтвердить точный репозиторий и его видимость; не использовать похожий
  публичный проект вместо согласованного приватного.
- Проверить конкретный source payload и историю перед отправкой: исключить
  `.env`, конфигурацию с ключами, signing material, caches, userdata и auth.
- Сверить подпись, SHA-256 и source snapshot готовой APK; приложить полные
  соответствующие исходники и лицензии, не только incremental overlay.
- Проверить новые permissions, exported components, зависимости и сетевые
  обращения; выполнить доступные проверки уязвимостей без выдачи skipped за PASS.
- Проверить release description и assets на приватные пути, содержимое аккаунтов
  и ложные заявления о завершённости или покрытии тестами.

Эти пункты — release gate, не заявление, что текущий локальный draft его прошёл.
